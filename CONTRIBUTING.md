# Contributing

Thanks for helping improve **From Zero to Fullstack Cheatsheets**!

## Editorial principles

- **Beginner-first:** explain prerequisite concepts and provide installation steps from scratch.
- **Reproducible:** document exact commands, expected outcomes, and troubleshooting.
- **Project-grounded:** reference the corresponding chapter repository and source files.
- **Accurate status:** distinguish implemented, tested work from uncommitted development and future recommendations.
- **Secure examples:** use placeholders, never real credentials, tokens, database URLs, or `.env` secrets.
- **English-first documentation:** write clear technical English suitable for reusable reference material.
- **Dual format:** Markdown is the editable source of truth; export reviewed guides as PDF.

## Review checklist

- [ ] Goal, prerequisites, supported operating systems, and system requirements are clear.
- [ ] Installation from a fresh machine and verification are documented.
- [ ] Code snippets, commands, and expected results are verified or marked illustrative.
- [ ] Configuration and file paths match the stated project version.
- [ ] Credentials and other sensitive material are absent.
- [ ] Common errors, fixes, and security practices are included.
- [ ] Quick reference and reuse checklist are provided.
- [ ] Links work and the PDF matches the Markdown.

## Contribution workflow

1. Propose a topic or improvement in an issue.
2. Create a focused branch and update the Markdown.
3. Verify the instructions against the source chapter or a clean setup.
4. Regenerate and review the PDF.
5. Submit a pull request explaining what was tested.

A chapter index is not a finished cheatsheet. Only label a guide **Published** once its content and examples have been reviewed.
